# 11. Manual Tests บนเบราว์เซอร์ (T1–T4) และเกณฑ์ผ่าน

> ครอบคลุมโจทย์ข้อ 1.6: ทดสอบอย่างน้อย 3 กรณี + ตรวจสอบด้วยการคำนวณมืออย่างน้อย 1 กรณี
> ชุดข้อมูลมาตรฐาน SET-A = P1=5, P2=3, P3=8 (q=2) — ตารางคำตอบอยู่ที่ [07-HAND-CALCULATION §7.5](07-HAND-CALCULATION.md)

## T1 — กำหนด BT เอง และเปรียบเทียบทั้งสามอัลกอริทึม

1. เปิด http://localhost:3000 → ตั้งจำนวนโปรเซส = 3
2. เลือกโหมด "กรอกด้วยตนเอง" กรอก P1=5, P2=3, P3=8
3. เลือกทั้ง 3 อัลกอริทึม, q = 2 → กด "คำนวณ"
4. เทียบทีละช่องกับตารางคำตอบ §7.5 — ต้องตรงทุกค่า ทุกอัลกอริทึม รวมถึง AVG WT และ Gantt chart
5. บันทึกภาพหน้าจอใช้ในรายงาน

**การตรวจสอบด้วยการคำนวณมือ (ตามที่โจทย์กำหนด)**: ใช้กรณีนี้ โดยแสดงวิธีคิดของ RR q=2 ทีละขั้นจากตารางวนคิว [07-HAND-CALCULATION §7.4](07-HAND-CALCULATION.md) แล้วเทียบกับที่โปรแกรมแสดง — ครบทั้ง ST, CT, TAT, WT, AVG WT

## T2 — สุ่ม BT และตรวจว่าคำนวณครบทุกโปรเซส

1. ตั้งจำนวนโปรเซส = 10 → โหมด "สุ่ม" → กด "สุ่มใหม่" 1 ครั้งเพื่อ fix ชุดค่า
2. จดค่า BT ทั้ง 10 ตัวที่แสดง → กด "คำนวณ" (ทั้ง 3 อัลกอริทึม)
3. Checklist:
   - [ ] ตารางมีครบ P1–P10 ทุกอัลกอริทึม ทุกช่องไม่ว่าง ไม่ NaN
   - [ ] BT ทุกตัวเป็นจำนวนเต็มบวก ช่วง 1–10
   - [ ] CT ของโปรเซสที่จบท้ายสุด = ΣBT (คิดจากค่าที่จดไว้)
   - [ ] AVG WT = ΣWT ÷ 10 ตรงที่แสดง (ทศนิยม 2 ตำแหน่ง)
   - [ ] กด "สุ่มใหม่" แล้วคำนวณใหม่ → ผลเปลี่ยนตาม BT ชุดใหม่

## T3 — ชุดข้อมูลเดิม เปลี่ยน Time Quantum

1. ใช้ SET-A (P1=5, P2=3, P3=8) เลือกเฉพาะ RR
2. รัน q = 1, q = 2, q = 4 โดยไม่แก้ BT
3. Checklist:
   - [ ] AVG WT ต่างกันตาม q (q เล็ก → context switch บ่อย → WT รวมสูงขึ้นในโมเดลนี้)
   - [ ] เวลาสิ้นสุดรวม (segment สุดท้ายของ Gantt) = 16 ทุกกรณี
   - [ ] q = 4 ผลเท่า FCFS หรือไม่ อธิบายเหตุผลได้ (ลำดับคิวยังวนตาม RR แต่ไม่มี preempt — ดู U-R2)
4. บันทึกภาพเทียบ 3 ค่า q ใช้ในรายงาน

## T4 — Validation

ทำบนหน้าเว็บทีละกรณี ตรงกับ unit test U-V1…U-V9 ([10-UNIT-TESTS §10.6](10-UNIT-TESTS.md)):

| ขั้นตอน | ต้องเห็น |
|---|---|
| เว้นจำนวนโปรเซสว่าง กดคำนวณ | E1 + ไม่มีผลลัพธ์ |
| จำนวนโปรเซส = 0 → คำนวณ | E2 |
| จำนวนโปรเซส = 3, เว้น BT ของ P2 ว่าง → คำนวณ | E4 ระบุ P2 + ขอบช่องแดง |
| เว้น BT ว่าง 2 แถวขึ้นไป | E5 |
| BT ของ P3 = -2 (หรือ 0, 2.5) | E4 ระบุ P3 |
| เลือก RR แล้ว q = 0 (หรือว่าง) | E6 |
| ยกเลิกอัลกอริทึมทั้งหมด → คำนวณ | E7 |
| แก้ข้อมูลให้ถูกแล้วคำนวณใหม่ | error หายไป + ผลลัพธ์แสดง |

## เกณฑ์ผ่านรวม (Acceptance Criteria)

- Unit test ผ่าน 100% (`npm run test`)
- **T1 ตรงกับค่าคำนวณมือทุกช่อง** — เป็นหลักฐานหลักว่าโปรแกรมถูกต้อง
- T2, T3 ผ่านทุก checklist
- T4: ทุกกรณีผิดมีข้อความแจ้งเตือน และโปรแกรมไม่แสดงผลลัพธ์จากข้อมูลที่ผิด

## สิ่งที่ต้องมีในรายงาน (จากแผนทดสอบนี้)

1. ภาพหน้าจอ T1 พร้อมตารางคำนวณมือเทียบทีละค่า
2. ภาพหน้าจอ T3 สามค่า q
3. ภาพหน้าจอ validation อย่างน้อย 3 กรณี (เลือกจาก T4)
4. ผลการรัน `npm run test` แสดงจำนวน test ที่ผ่าน
