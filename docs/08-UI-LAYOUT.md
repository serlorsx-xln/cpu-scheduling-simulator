# 8. UI Layout และพฤติกรรมหน้าจอ

> ข้อความ error / styling / a11y อยู่ที่ [09-UI-VALIDATION-UX](09-UI-VALIDATION-UX.md) · กฎ validation ที่ [02-REQUIREMENTS §2.5](02-REQUIREMENTS.md)

หน้าเดียว แบ่ง 3 โซนเรียงจากบนลงล่าง: **ฟอร์มรับข้อมูล → ข้อผิดพลาด (ถ้ามี) → ผลลัพธ์รายอัลกอริทึม**

## 8.2 พฤติกรรมโซน A1 — จำนวนโปรเซส

- ช่องตัวเลข (type number, min 1 max 10)
- เปลี่ยนค่า → สร้าง/ลดแถว P1…Pn ทันที (ค่า BT ที่กรอกไว้คงอยู่ตาม index ที่ยังมี)

## 8.3 พฤติกรรมโซน A2 — Burst Time

- **โหมดสุ่ม**: สุ่มจำนวนเต็ม 1–10 ใส่ตาราง ช่อง input เป็น readonly แต่ยังแสดงค่า (ผู้ใช้เห็นชุดข้อมูลที่ใช้จริง) ปุ่ม "สุ่มใหม่" สุ่มซ้ำ
- **โหมดกรอกเอง**: ช่อง input เปิดให้แก้ไขทุกแถว
- สลับโหมดไม่ลบค่าที่กรอกไว้ — กลับมาโหมดกรอกเองแล้วเจอค่าเดิม

## 8.4 พฤติกรรมโซน A3 — อัลกอริทึมและ Time Quantum

- Checkbox 3 ตัว เลือกได้มากกว่า 1
- ช่อง Time Quantum: **แสดงเฉพาะเมื่อเลือก RR**, default = 2
- ปุ่ม "คำนวณ": validate → simulate → render (data flow ใน [03-ARCHITECTURE §3.4](03-ARCHITECTURE.md))
- ปุ่ม "ล้างค่า": reset ทุก state กลับค่าเริ่มต้น (n=3, โหมดสุ่ม, ทุกอัลกอริทึมเลือก, q=2, ไม่มีผลลัพธ์)

## 8.5 พฤติกรรมโซน B — ข้อผิดพลาด

- กล่องแดงเหนือโซน C แสดง `ValidationIssue[]` ทั้งหมดเป็น bullet
- ช่อง/แถวที่ผิด: ขอบแดง + ข้อความ inline ใต้ช่อง (ใช้ `processId` ระบุแถว)
- มี error = โซน C ว่างเปล่า (ไม่แสดงผลลัพธ์เก่าค้าง)

## 8.6 พฤติกรรมโซน C — การ์ดผลลัพธ์ต่ออัลกอริทึม

- หัวการ์ด: ชื่ออัลกอริทึม (RR แสดง "Round Robin (q = 2)" ตามค่าที่ใช้จริง)
- ตาราง Process | BT | ST | CT | TAT | WT — **เรียงตาม P1…Pn เสมอ** (แม้ SJF รัน P2 ก่อน)
- แถบสรุปใต้ตาราง: `AVG WT = x.xx` (ตัวหนา — ค่าที่โจทย์บังคับ) + `AVG TAT = x.xx` (รอง)
- Gantt chart: แถวเดียว ช่องสีต่างกันต่อโปรเซส กว้าง ∝ ความยาว segment แสดง "P1 / 0–5" ในช่อง; โปรเซสเดียวกันได้ CPU ต่อเนื่องหลาย segment (RR) แสดงแยก segment ตามจริง
- ผลลัพธ์ทั้งหมดใช้ชุดข้อมูลเดียวกัน เปรียบเทียบข้างกันได้ในหน้าเดียว
